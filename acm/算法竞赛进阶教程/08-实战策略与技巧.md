## 8.1 反悔贪心

### 思想

贪心常错在"当前最优 ≠ 全局最优"。**反悔贪心**的做法是：先按贪心策略走，一旦发现后面有更好的选择，就把之前的选择"撤销"掉。

### 例 1：建筑抢修（P4053）

**问题**：$n$ 个任务，每个有耗时 $t_i$ 与截止时间 $d_i$，求最多能完成几个。

**做法**：按截止时间排序，依次尝试：

- 若当前总耗时 + $t_i \le d_i$：接下这个任务（入堆）；
- 否则：若已接任务中耗时最长的那个 $> t_i$，就**替换掉它**（反悔）。

```cpp
// ==================== 反悔贪心：建筑抢修 ====================
// tasks[i] = {耗时, 截止时间}
long long repairSchedule(std::vector<std::pair<long long,long long>> tasks) {
    std::sort(tasks.begin(), tasks.end(),
              [](const std::pair<long long,long long> &a, const std::pair<long long,long long> &b) {
                  return a.second < b.second;
              });
    std::priority_queue<long long> pq;      // 大根堆：已接任务的耗时
    long long now = 0, cnt = 0;
    for (auto &t : tasks) {
        if (now + t.first <= t.second) {    // 能接就接
            now += t.first;
            pq.push(t.first);
            ++cnt;
        } else if (!pq.empty() && pq.top() > t.first) {   // 反悔：换掉最耗时的
            now += t.first - pq.top();
            pq.pop();
            pq.push(t.first);
        }
    }
    return cnt;
}
```

### 例 2：Buy Low Sell High（CF865D）

**问题**：已知未来 $n$ 天股价，每天可买一股或卖一股（也可以不动），求最大收益。

**做法**：用小根堆维护"可买点"。每天：

- 若堆顶 < 今天价格：**先卖**（收益 += 今天价 − 堆顶），再把今天价格**入堆两次**（一次表示正常买、一次表示"反悔"——相当于把之前那笔卖单改成今天的买入点）；
- 否则：今天价格入堆（作为潜在买点）。

```cpp
// ==================== 反悔贪心：CF865D Buy Low Sell High ====================
long long maxProfit(const std::vector<long long> &price) {
    std::priority_queue<long long, std::vector<long long>, std::greater<long long>> pq;
    long long profit = 0;
    for (long long p : price) {
        if (!pq.empty() && pq.top() < p) {
            profit += p - pq.top();
            pq.pop();
            pq.push(p);        // 反悔位：允许把这次卖出改成买入
        }
        pq.push(p);
    }
    return profit;
}
```

**反悔贪心的通用套路**：

1. 把"选择"抽象成"配对/覆盖/占用资源"；
2. 用堆维护当前选择；
3. 当出现更优的选择时，弹出最差的选择并替换；
4. 有时需要"入堆两次"来实现"撤销上一次决策"。

## 8.2 构造题方法论

构造题（"请给出一种方案"）没有固定算法，但有固定套路：

| 套路 | 说明 | 例子 |
|---|---|---|
| **从特殊到一般** | 先解决 $n$ 很小或特殊形态的情况，再推广 | 先做链、再做树 |
| **归纳构造** | 假设 $n-1$ 有解，构造 $n$ 的解 | 递归/倍增构造 |
| **调整法** | 任取一个解，证明能通过有限步调整变优且不违反约束 | 交换论证 |
| **逆推** | 从目标状态倒推回初始状态 | 逆向操作 |
| **分类讨论** | 按奇偶、模数、大小关系分类 | 大部分构造题 |
| **打表找规律** | 暴力打小数据，找规律再构造 | 序列构造题 |
| **对称构造** | 用对称性保证约束满足 | 矩阵构造 |
| **贪心 + 交换论证** | 证明"任何最优解都能通过交换变成贪心解" | 排序贪心题 |

**实战建议**：

1. 先用暴力写一个"能过小数据"的搜索/DP；
2. 打表输出小规模的答案，观察规律；
3. 猜规律 → 构造 → 用暴力验证中等规模（对拍）；
4. 最后写正式构造代码。

**经典题**：[P1338 末日的传说](https://www.luogu.com.cn/problem/P1338)（逆序对构造）、[P2119 魔法阵](https://www.luogu.com.cn/problem/P2119)（枚举构造）、[P1561 爬山](https://www.luogu.com.cn/problem/P1561)、[CF 构造标签题](https://codeforces.com/problemset?tags=constructive+algorithms)。

## 8.3 交互题

### 特点

你的程序与评测机的"交互库"来回通信：你输出询问，它返回回答。**你无法看到完整输入**。

### 必备技巧

**1. 输出后必须 flush**，否则会 TLE/RE：

```text
// 交互题输出模板
std::cout << "? " << x << std::endl;      // endl 会 flush（最省事但略慢）
// 或
std::cout << "? " << x << "\n" << std::flush;
// C 风格
printf("? %d\n", x);
fflush(stdout);
```

**2. 严格遵守询问次数限制**：题目通常给出 $Q_{\max}$，超了直接判错。

**3. 常见交互类型**：

| 类型 | 策略 |
|---|---|
| 猜数（每次问"大了还是小了"） | 二分 |
| 猜排列（每次询问一段的性质） | 分治 / 随机化 |
| 询问集合的交/并信息 | 线性基 / 分组编码 |
| 需要"找到某个特殊元素" | 随机采样 + 验证（$O(\log)$ 次期望命中） |
| 询问返回值带随机错误 | 多次询问取多数（容错） |

**4. 随机化在交互题中的巨大威力**：

- 若目标元素有 $\ge 1/2$ 的概率被随机选中，则随机 $30$ 次几乎必中；
- 用随机权值/随机采样把"确定性构造"变成"高概率成功"。

**5. 调试技巧**：本地写一个假的交互库（读你的输出、返回答案），用它对拍。

**经典题**：[CF679A Bear and Prime 100](https://codeforces.com/problemset/problem/679/A)（入门）、[CF1466E Apollo versus Pan](https://codeforces.com/problemset/problem/1466/E)（非交互但值得练位运算）、[P5891 交互题选集]（洛谷交互题标签）。

## 8.4 随机化算法

### 四类常用随机化

| 类型 | 用途 | 关键点 |
|---|---|---|
| **随机化哈希** | 判断两个集合/子树是否相同 | 给每个元素随机权值，比较权值和/异或和 |
| **随机化判定** | 判定多项式恒等（Schwartz–Zippel） | 随机取值代入，错误概率 $\le \deg/p$ |
| **随机化贪心 / 多次尝试** | 构造题的"碰运气"解法 | 随机初始顺序，跑多次取最优 |
| **模拟退火 / 爬山** | 最优化问题求近似最优 | 见数学教程第 10 章 |

### 例：Schwartz–Zippel 引理的应用

要判断两个多项式 $f, g$ 是否恒等（不能展开比较）：随机取 $x_0$，比较 $f(x_0)$ 与 $g(x_0)$。若不等则一定不等；若相等则有 $\le \deg/p$ 的概率误判。多取几个点即可把错误率降到可忽略。

**典型应用**：字符串匹配的随机化（两个子串是否相同）、集合相等性判定、树上路径哈希。

### 例：随机化求"期望最大值"

某些问题要求"最大化某个量"，正解是复杂 DP，但随机化贪心（多次随机 + 局部调整）在时限内能拿到接近最优的答案。**注意：只适用于"答案允许近似"或"出题人没卡"的题。**

## 8.5 卡常与工程技巧

### 输入输出

```cpp
// 1) 最快：手写 fread 读入（适用于 1e6 以上的输入）
namespace FastIO {
    const int BUFSIZE = 1 << 20;
    char buf[BUFSIZE];
    int bufLen = 0, bufPos = 0;
    inline char getChar() {
        if (bufPos == bufLen) {
            bufLen = (int)fread(buf, 1, BUFSIZE, stdin);
            bufPos = 0;
            if (bufLen == 0) return 0;
        }
        return buf[bufPos++];
    }
    inline long long readLongLong() {
        char c = getChar();
        while (c && (c < '0' || c > '9') && c != '-') c = getChar();
        bool neg = false;
        if (c == '-') { neg = true; c = getChar(); }
        long long x = 0;
        while (c >= '0' && c <= '9') { x = x * 10 + (c - '0'); c = getChar(); }
        return neg ? -x : x;
    }
}

// 2) 常用：关闭同步 + 解除 cin/cout 绑定
// std::ios::sync_with_stdio(false);
// std::cin.tie(nullptr);

// 3) 输出用 putchar / '\n'（不要用 endl）
```

### 常数优化清单

| 技巧 | 效果 |
|---|---|
| 用 `int` 代替 `long long`（在不会溢出时） | 明显（寄存器/缓存压力小） |
| 减少取模：用条件减法代替 `%` | 明显 |
| 循环内减少函数调用（把 `min/max` 手写开） | 中等 |
| 数组连续访问（缓存友好），把二维压成一维 | 明显 |
| 用 `bitset` 做位运算批量处理 | 巨大（$\div 64$） |
| `__builtin_popcount` / `ctz` / `clz` | 中等 |
| 把频繁访问的变量放局部（编译器更好优化） | 中等 |
| 手写栈避免递归（同时避免爆栈） | 中等 |
| 提前 `break` / 剪枝 | 视题目 |
| `#pragma GCC optimize("O3")` | 小（多数 OJ 已开 O2） |

### 空间优化

- 用 `short`/`char` 存小值域数据；
- 二维数组按"行连续"访问（C++ 行优先）；
- 用 `vector` 而非定长数组可减少内存峰值（但更慢）；
- `bitset` 代替 `bool` 数组（省 8 倍）。

### 调试期实用宏


## 8.6 对拍与调试

### 标准对拍流程

1. **写暴力**（`brute.cpp`）：正确但慢；
2. **写正解**（`sol.cpp`）；
3. **写数据生成器**（`gen.cpp`）：用随机种子生成小数据；
4. **写对拍脚本**：循环跑，比对输出，不一致就停下来保存数据。

```powershell
# ==================== Windows 对拍脚本（PowerShell） ====================
# 用法：pwsh -File tools\stress.ps1
$ErrorActionPreference = "Stop"
for ($i = 1; $i -le 1000; $i++) {
    $seed = $i
    & .\gen.exe $seed > in.txt
    & .\sol.exe  < in.txt > out1.txt
    & .\brute.exe < in.txt > out2.txt
    if ((Get-Content out1.txt -Raw) -ne (Get-Content out2.txt -Raw)) {
        Write-Host "WA on seed $seed" -ForegroundColor Red
        Copy-Item in.txt "wa_$seed.txt"
        break
    }
    if ($i % 50 -eq 0) { Write-Host "ok $i" }
}
```

### 调试的六个检查点

1. **数组越界**（`-fsanitize=address` 或本地开 `-D_GLIBCXX_ASSERTIONS`）；
2. **溢出**（`long long` 是否够？中间乘法是否溢出？）；
3. **未初始化**（多组数据的清空）；
4. **边界**（$n=1$、空集、全相同、极值）；
5. **死循环 / 爆栈**（递归深度）；
6. **浮点误差**（eps 选择）。

### 编译选项建议

```bash
# 平时调试（会变慢，但能抓出 UB）
g++ -std=c++17 -O1 -g -fsanitize=address,undefined -D_GLIBCXX_ASSERTIONS -o sol sol.cpp

# 提交/对拍（接近评测机）
g++ -std=c++17 -O2 -o sol sol.cpp
```

## 8.7 比赛策略

### 时间分配（个人赛，5 小时）

| 阶段 | 时间 | 任务 |
|---|---|---|
| 读题 | 0:00–0:15 | **全部读完**，标记难度与类型 |
| 抢分 | 0:15–1:30 | 先做签到题与熟悉类型 |
| 主攻 | 1:30–4:00 | 攻克 2~3 道中档题 |
| 冲刺 | 4:00–5:00 | 卡住的题换思路 / 检查已过题 |

### 团队赛分工

- **读题分工**：每人负责 3~4 题，读完互相汇报；
- **主攻方向**：按各自擅长板块分配（你已有：字符串 / DP / 数学 / 数据结构基础）；
- **交接机制**：卡题 20 分钟无进展就换人。

### 提交前检查清单

- [ ] 多组数据是否清空？
- [ ] 数组大小是否够（含 +5 冗余）？
- [ ] 输出格式对不对（换行、空格、大小写）？
- [ ] 是否会溢出（`int` → `long long`）？
- [ ] 边界情况（$n=1$、$m=0$、空串）？
- [ ] 复杂度是否真的能过（常数是否过大）？
- [ ] 交互题是否 flush？

## 8.8 常见思维陷阱

| 陷阱 | 表现 | 对策 |
|---|---|---|
| **误判复杂度** | 以为 $O(n\sqrt n)$ 能过 $10^6$ | 先估算常数（$\sqrt{10^6}=1000$，$10^9$ 次操作基本过不了） |
| **过度优化** | 在签到题上写复杂数据结构 | 先写最朴素的能过版本 |
| **忽视特判** | 只测了随机数据 | 手造边界数据 |
| **死磕一题** | 一道题卡 1.5 小时 | 设 30 分钟止损线 |
| **不看题面细节** | 忽略了"恰好"、"至少"、"不重复" | 逐字读题，做标记 |
| **凭直觉建模** | 网络流建模想当然 | 用小数据手算验证建模 |
| **忽略取模** | 答案要求取模却输出了原值 | 提交前核对输出要求 |
| **重写而非修改** | 代码写崩后重写 | 先保存版本，小步修改 |
