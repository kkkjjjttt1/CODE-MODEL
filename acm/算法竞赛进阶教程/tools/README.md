## 1. `check.ps1` —— 代码块编译检查

从教程所有 Markdown 文件中提取 C++ 代码块，逐个做语法与语义检查。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\check.ps1
```

**做法**：

- 每个代码块单独抽取，自动补上公共头文件与常用函数声明（只放声明，避免与块内定义冲突）；
- 依次尝试三种形态：**原样编译** → **拼接该文件前文（长度上限 40000 字符）后编译**（解决跨代码块依赖）→ **包在函数体内编译**（解决片段式代码）；
- 三者都失败才计为失败，错误信息写入 `%TEMP%\acm_math_check_report.txt`。

**当前状态**：46 个代码块，**0 失败**。

> 说明：本机 MinGW-w64 GCC 8.1 的 `<bits/stdc++.h>` 自身有缺陷（`std::filesystem` 头在 C++17 下报错），所以检查脚本用具体头文件替代；教程正文按惯例仍写 `#include <bits/stdc++.h>`。
> 另外，**框架示意型代码块**（如 IDA\*、双向 BFS、Alpha-Beta 的通用骨架，含未定义的 `State` 类型）标记为 `text` 而非 `cpp`，因为它们本身就是伪代码。

## 3. 对拍发现的真实 bug（已修正并写进教程）

| # | 算法 | 现象 | 根因 | 修正 |
|---|---|---|---|---|
| 1 | **KM（带权匹配）** | 某些权值下死循环 | 流行的"递归版"在顶标调整后交错树结构变化，旧 `slack` 失效导致 `d = 0`，顶标不再变化 | 改用 **BFS 版**（每次增广重建交错树），见第 02 章 |
| 2 | **整体二分** | 答案偏小 | 每层都用 `a[i] <= mid` 加入元素，递归到**右半值域**时把已排除的元素也算进去了 | 改为只加入 `vl <= a[i] && a[i] <= mid`，见第 05 章 |
| 3 | **DLX** | 偶尔死循环 | 找到解后提前 `return` 之前仍执行了一次 `resume`，造成重复恢复、链表损坏 | 把 `if (found) return;` 提到恢复语句**之前**，见第 07 章 |
| 4 | **DLX** | 行数 > 列数时结果错误 | `head` 数组按**行**索引，`init` 却只清了 `colCnt` 个 | `init(colCnt, rowCnt)` 清够行数，见第 07 章 |
| 5 | **长链剖分** | 某些点答案偏大 | 公用缓冲区的分配指针初值为 0，与"根所在长链的段"重叠，`f` 数组互相覆盖 | `bufPtr` 初值必须是 `dep[1]`，见第 03 章 |

**这 5 个都是"语法正确、样例能过、随机对拍才暴露"的坑**——也正说明了为什么每个模板都要做随机对拍。

> 另外还有若干问题出在**对拍程序自身**（例如暴力遍历子树时忘了排除父节点、状态数组跨轮次未清空、双向 BFS 的图不可逆），这些不属于教程代码缺陷，但同样说明"对拍也要写对"。

## 4. 自己写对拍的建议

1. **暴力要独立实现**：不要抄模板，否则同错同对；
2. **数据要小但随机**：$n \le 30$ 通常够暴露边界，先跑小数据；
3. **覆盖极端情况**：全相同、链、菊花、只有一个点、空集、菱形图；
4. **状态要清干净**：多轮迭代时最容易因残留数组产生假阳性/假阴性；
5. **对拍程序本身也要"人对"**：当正解与暴力不一致时，先怀疑暴力。
