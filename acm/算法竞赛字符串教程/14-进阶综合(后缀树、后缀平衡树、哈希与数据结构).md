# 第 14 章 进阶综合：后缀树、后缀平衡树、哈希 × 数据结构、树上字符串

## 14.1 后缀树（Suffix Tree）

### 14.1.1 是什么

把所有后缀插入一棵 **压缩 Trie**（把没有分支的链压缩成一条带长度标签的边），得到后缀树。叶节点 = 后缀；从根走到某点的路径 = 一个子串。构造 Ukkonen 算法 O(n)（概念复杂，几乎不手写）。

### 14.1.2 与 SA / SAM 的关系（省心结论）

- 后缀数组 + height 数组本质上是后缀树的**DFS 序 + 相邻叶 LCP**：树上 LCA 的深度（= LCP）对应区间 RMQ of height；
- **后缀树 ≈ 反串的 SAM 的 link 树**：对 `reverse(s)` 建 SAM，它的 link 树就是 s 的后缀树（压缩边后）——所以**想要后缀树的功能，直接用 SAM 或 SA 即可**；
- 后缀树三大经典应用（最长重复子串、本质不同子串、模式出现区间）在 09/10 章都有对应 O(n)/O(n log n) 做法。

> 竞赛结论：**需要"后缀树"特性的题，99% 可以用 SA + 区间、或 SAM + link 树替代**；真手写后缀树的情况极少（最多在论文题里出现）。

## 14.2 后缀平衡树（Suffix Balanced Tree）

### 14.2.1 问题

动态维护一个字符串集合，支持**在线插入 / 删除**一个字符串，并随时**按字典序**回答"某串排第几 / 排名相邻"等。静态版（后缀数组）不支持插入，SAM 是增量式但只能"尾部加字符、不能删中间"。

### 14.2.2 做法概要

用平衡树（替罪羊树最常用）按**字符串字典序**为键维护集合；节点比较两个字符串时用**哈希 + 二分 LCP**（O(log n) 比较一次）。总复杂度 O(插入次数 × log²n) 上下。也可以"每次比较用 O(1) 的 rank 标号"技巧（给每个节点标一个字典序序号的实数，靠标号比较），实现更高效但复杂。

### 14.2.3 什么时候用

- "动态后缀排序"的题很少，真遇到优先考虑是否能用**离线 + 最终版本**代替（把所有可能字符串先收集，静态后缀数组/SAM 处理）；
- 经典例子：某些"操作序列最后询问"可反推成静态问题。**先想离线**，后缀平衡树是最后的备选。

## 14.3 线段树 / 平衡树维护哈希（支持修改的字符串）

### 14.3.1 问题

给定串 s，支持：
- 单点/区间修改字符；
- 询问两个子串是否相等 / 是否回文 / 比较大小。

哈希在 02 章是"静态"的；现在把**前缀哈希改成线段树维护的区间哈希**，就能支持修改。

### 14.3.2 线段树合并公式

记线段树节点存该区间串的哈希 `h`（与 02 章同样的 base 进制，长度 len 已知）：

```
节点 = 左儿子 || 右儿子
h  = hL * base^{lenR} + hR
```

查询任意区间得到其哈希 O(log n)；任意两个子串判等 O(log n)；判回文 = 正串哈希 == 反串哈希（建两棵线段树：原串一棵 + 反串一棵，区间坐标映射）。

```cpp
// 示意（线段树静态数组版，n ≤ 1e5）：
// pull: t[p].h = (t[lc].h * pw[t[rc].len] + t[rc].h) % MOD
// 查询返回 (hash, len) 二元组，两段拼接时套用同一公式
// 修改: 单点把字符改为 c → 叶节点 h = c，一路 pull
```

> [洛谷 P4036 [JSOI2008] 火星人（即 BZOJ 1014）](https://www.luogu.com.cn/problem/P4036)（经典）：单点改 + 插入字符 + 查两后缀 LCP → splay 维护区间哈希（支持中间插入）；不会 splay 的用平衡树/块状链表，思路一致。**LCP 用二分 + 区间哈希判定**。

### 14.3.3 相关技巧

- 区间哈希 + 二分 = 区间 LCP / 回文半径（带修改也能做）；
- 值域离散或双哈希防碰撞照旧适用；
- 树上同理：把树链哈希放进树链剖分的线段树里。

### 14.4.2 树上的"本质不同串"：SAM on Trie / 广义 SAM

若问题变成"统计树上所有根到叶路径 / 所有路径子串的本质不同个数"，做法通常是把树上结构**建成一棵 Trie**（如 [P3346 诸神眷顾的幻想乡](https://www.luogu.com.cn/problem/P3346)：树叶子少，根到叶路径有限），再对 Trie 跑**广义后缀自动机**（10 章 ⑦）——Trie 的每个节点作为一个"前缀状态"插入，SAM 节点数 O(Trie 点数)。这是树上字符串问题的标准解法之一。

### 14.4.3 树哈希（判定同构，顺带一提）

给树找一个与"形态"绑定的哈希值（如 AHU 算法 / 深度+子树排序哈希），用于判定两棵子树同构、树同构。属于树论+哈希的交叉，需要时查 OI-wiki《树哈希》。

## 14.5 二维哈希（子矩阵匹配）

把哈希推广到矩阵：对每行先做**横向一维哈希**得到"行哈希数组"，再对列做**纵向组合**（以行哈希为元素再做一次滚动哈希）。子矩阵哈希 O(1) 查询，可判"矩阵 A 是否在矩阵 B 中出现 / 有多少个本质不同子矩阵"。构建 O(nm)，参考 02 章公式在行、列两个方向各一遍。

## 14.7 小结：遇到"字符串 + 数据结构"题怎么想

1. **离线化优先**：能否把动态问题倒过来变成静态？（能 → SA/SAM 走起）
2. 确定"比较/相等"的原语：哈希（要防碰撞）、还是 LCP/SA 区间、还是自动机状态；
3. 修改操作 → 线段树/平衡树维护哈希或转移；
4. 树上 → 根前缀哈希 + 倍增、Trie 化 + 广义 SAM；
5. 多个串 + 区间/出现次数 → SAM link 树 + 线段树合并（重量级，最后考虑）。
