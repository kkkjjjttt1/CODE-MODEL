# 验证工具说明

本目录存放用于**校验教程代码正确性**的工具。教程中出现的每一个 C++ 代码块都经过了下述检查。

---

## 1. `check.ps1` —— 代码块编译检查

从教程所有 Markdown 文件中提取 ` ```cpp ` 代码块，逐个做语法与语义检查。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\check.ps1
```

**它的做法**：

- 每个代码块单独抽取，自动补上公共头文件与常用函数声明（只放声明，避免与块内定义冲突）；
- 依次尝试三种形态：原样编译 → 拼接"该文件之前所有代码块"后编译（解决跨代码块的依赖）→ 包在函数体内编译（解决片段式代码）；
- 全部失败才计为失败，并打印前若干行错误信息，完整报告写入 `%TEMP%\acm_math_check_report.txt`。

**当前状态**：103 个代码块，0 失败。

> **注意**：本机 MinGW-w64 GCC 8.1 的 `<bits/stdc++.h>` 自身存在缺陷（`std::filesystem` 头在 C++17 下报错），因此检查脚本用具体头文件替代 `bits/stdc++.h`。教程正文仍按惯例写 `#include <bits/stdc++.h>`。

## 2. 三个对拍验证程序

编译并运行：

```powershell
g++ -std=c++17 -O2 -o tools\verify_nt.exe   tools\verify_nt.cpp   ; .\tools\verify_nt.exe
g++ -std=c++17 -O2 -o tools\verify_more.exe tools\verify_more.cpp ; .\tools\verify_more.exe
g++ -std=c++17 -O2 -o tools\verify_misc.exe tools\verify_misc.cpp ; .\tools\verify_misc.exe
```

每个程序都会打印 `[ok]` / `[FAIL]` 与最终统计，失败时返回非零退出码。

## 3. 验证发现并修正的问题

对拍过程中发现了一处教程代码的真实缺陷，已修正：

- **单纯形法**：最初版本的单纯形表没有显式保存**松弛变量列**。松弛变量虽在初始基中是单位列，但转轴后会出现非零检验数、可能重新进入基；漏掉这些列会让程序误判"已最优"提前终止。
  反例：`max x1 + 2x2, s.t. x1+x2 ≤ 3, x1 ≤ 2, x2 ≤ 2`，错误版本返回 4，正确值应为 5。
  修正后与暴力枚举顶点法在 40 组随机线性规划上完全一致。

这类"语法正确但结果错误"的问题，只有通过对拍才能发现 —— 这也是本目录存在的意义。
